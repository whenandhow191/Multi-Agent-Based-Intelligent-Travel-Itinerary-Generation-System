# 第四章“1+4 Agent 分别实现”实现说明

> 对应开发路线：C18～C22
> 完成日期：2026-09-13
> 目标：说明 Coordinator 与四个业务 Agent 的文件、逻辑、输入输出、权限、失败规则和复现方法

## 1. 完成结果

第四章在第三章 Harness 之上完成了一个 Coordinator 和四个业务 Agent。“1+4”不是五个 Agent 互相调用：Coordinator 只提出任务图，Harness 负责状态、依赖、并发、重试、超时和权限，业务 Agent 只通过结构化 Artifact 交接。

```text
TripRequest
    |
CoordinatorBrain --阻塞问题--> WAITING_USER
    |
    +--> A1 Destination Intelligence ----+
    +--> A2 Mobility & Lodging -----------+--> Harness 合并候选
                                                |
                                      Harness build_route_matrix
                                                |
                                      A3 Itinerary Planning
                                                |
                                      A4 Critic & Risk
                                                |
                                      pass / PatchRequest
```

最终边界如下：

- A1/A2 可以并行，但不能互调；输出分别通过自己的 Pydantic Schema。
- A2 只能核验已有酒店/枢纽端点的定向路线，不能提前生成全量 POI 矩阵。
- A3 不联网；OR-Tools 负责候选选择，真实 Route 引用负责移动时间，最后再次确定性校验。
- A4 不直接修改任何事实，只报告问题并路由给真正拥有数据或方案的 Agent。
- 单元测试只用 `ScriptedModelGateway` 和进程内 Fixture Tool，不需要 API Key 或网络。

## 2. 四个业务 Agent 对应文件

用户所问的“四个 Agent”就是 A1～A4；Coordinator 是额外的“1”，不计入四个业务 Agent。

| 编号 | Agent | 主实现文件 | 输入 | 输出 |
|---|---|---|---|---|
| A1 | Destination Intelligence | `packages/agents/destination_intelligence.py` | 目的地、日期、兴趣和工具结果 | `DestinationIntelArtifact` |
| A2 | Mobility & Lodging | `packages/agents/mobility_lodging.py` | 出发地、目的地、日期、交通/住宿偏好和工具结果 | `MobilityLodgingArtifact` |
| A3 | Itinerary Planning | `packages/agents/itinerary_planning.py` | `TripRequest`、A1/A2 Artifact、Harness Route 矩阵 | `PlanCandidatesArtifact` |
| A4 | Critic & Risk | `packages/agents/critic_risk.py` | 请求、候选、A1/A2 Artifact、Route 矩阵 | `ReviewArtifact`/`CritiqueArtifact` |

相关文件：

- `packages/agents/coordinator.py`：实现 Coordinator/Brain。
- `packages/agents/__init__.py`：集中导出稳定公共 API。
- `packages/harness/agent.py`：所有模型型 Agent 共用的有限生命周期。
- `packages/harness/tool_gateway.py`：所有工具调用的唯一执行边界。
- `packages/domain/*.py`：共同遵循的请求、事实、证据、方案和审校契约。

## 3. C18：Coordinator / Brain

提交：`feat(agent): implement coordinator brain`

主文件是 `packages/agents/coordinator.py`。`CoordinatorBrain.decide()` 的逻辑：

1. 存在 `blocking=true` 的 `ClarificationQuestion` 时返回 `WAITING_USER`，不创建任务图。
2. 否则创建固定白名单 DAG：A1/A2 并行，Harness 合并候选并构造 Route 矩阵，再依次进入 A3、A4 和最终聚合。
3. `DispatchBudget` 限制任务数、并行度、模型调用、工具调用和最多两轮返工。
4. `CoordinatorTaskGraph` 拒绝重复 ID、缺失依赖、自依赖和环。
5. 输出不含 Place、Route、Claim 或价格，因此 Coordinator 不会伪造旅行事实。

Coordinator 输出声明式 `TaskBlueprint`，不含可执行回调。Harness 后续将它物化为第三章 `TaskDAG`，所以重试、取消、超时和状态迁移仍只有一个权威实现。

验收文件 `tests/test_coordinator.py` 覆盖固定 DAG、A1/A2 并行、Harness 路线矩阵节点、阻塞澄清和预算上限。

## 4. C19：A1 Destination Intelligence

提交：`feat(agent): implement destination intelligence agent`

主文件是 `packages/agents/destination_intelligence.py`。允许工具只有 `places.search`、`places.details`、`weather.forecast`、`public_page.read` 和 `entity.resolve`。

编写逻辑：

1. `DestinationIntelligenceAgent` 继承 `BaseAgent`，模型只能看见白名单工具的输入 Schema。
2. 供应商事实进入 `Place`/`WeatherForecast`；系统推断的游玩时长保存在独立 `VisitDurationEstimate`。
3. 价格无法获得时保留 `CostKind.UNKNOWN`，不能按 0 元处理。
4. `DestinationIntelArtifact` 包含候选、天气、Claim、Evidence、unknowns 和时间；旧名 `DestinationResearchArtifact` 是兼容别名。
5. Artifact 验证每个 Place、Weather 和 Claim 引用的 Evidence 都真实存在，并拒绝重复 ID。
6. A1 不能输出 `DailyItinerary`，因此不能决定最终顺序。

`tests/test_destination_intelligence.py` 先让 ScriptedModel 调用 `places.search` Fixture Tool，再返回 Artifact；删除被引用 Evidence 后输出会被拒绝。

## 5. C20：A2 Mobility & Lodging

提交：`feat(agent): implement mobility and lodging agent`

主文件是 `packages/agents/mobility_lodging.py`。允许工具只有 `routes.compute`、`lodging.search`、`flight.search`、`rail.official_link` 和 `currency.convert`。

编写逻辑：

1. 归一化 `IntercityTransport`、`Lodging`、已有端点 `Route` 和 `ConnectionRisk`。
2. `RouteScope` 固定为 `targeted_existing_endpoints`；全量矩阵必须等 A1/A2 合并后由 Harness 创建。
3. Artifact 验证交通、住宿和路线的 Evidence 引用闭包。
4. 价格未知、库存不是 `LIVE`、存在 `ProviderFailure` 或风险要求人工判断时，强制 `manual_confirmation_required=true`。
5. 人工确认还必须写明 `unknowns`，防止 UI 把参考班次或未知价格展示成已确认事实。
6. 旧名 `LogisticsArtifact` 是兼容别名。

`tests/test_mobility_lodging.py` 覆盖 ScriptedModel + `lodging.search` Fixture Tool、参考库存降级和未标人工确认时的 Schema 拒绝。

## 6. C21：A3 Itinerary Planning

提交：`feat(agent): implement itinerary planning agent`

主文件是 `packages/agents/itinerary_planning.py`。允许工具只有 `optimizer.solve`、`budget.calculate`、`schedule.validate` 和 `plan.variant`，没有联网搜索权限。

编写逻辑：

1. 排除用户禁止地点，将 `must_visit` 和固定预约地点设为 CP-SAT 必选变量。
2. 硬预算下，未知价格以 `budget_unverifiable` 失败；已知价格上界转为整数分约束，不可行返回 `hard_constraints_infeasible`。
3. 三种方案不只是改标题：均衡倾向更多候选；经济固定最少活动数并最小化费用；轻松固定最少活动数并最小化时长。
4. CP-SAT 固定随机种子、单 Worker，保证离线可重复。
5. 只使用传入 Route 矩阵的边找顺序；缺边返回 `route_matrix_incomplete`，不使用模型路程估计。
6. 排程应用路线耗时、开放时段、特殊闭馆、每日窗口、最大活动分钟和固定预约。预约必须保持精确起止时间，发生冲突则失败。
7. 每个行程项只引用已有 Place、Route、Claim、Evidence；最终用 `validate_itinerary()` 重算预算、时间窗、重叠、开放时间、坐标系和引用。
8. 输出含均衡、经济、轻松三种 `ItineraryVersion` 的 `PlanCandidatesArtifact`。

新增 `ortools` 已写入 `pyproject.toml` 和 `uv.lock`，安装在项目隔离环境。`tests/test_itinerary_planning_agent.py` 覆盖三种方案、ScriptedModel + `optimizer.solve`、硬预算失败和固定预约。

## 7. C22：A4 Critic & Risk

提交：`feat(agent): implement critic and risk agent`

主文件是 `packages/agents/critic_risk.py`。允许工具只有 `budget.calculate` 与 `schedule.validate`，没有事实搜索和方案修改权限。

编写逻辑：

1. `DeterministicCritic` 对每个候选重新执行 `validate_itinerary()`，不信任 A3 自报状态。
2. 将超预算、闭馆、时间窗、重叠、路线端点、坐标系、Claim/Evidence 缺失转换为 `HardViolation`。
3. 额外检查方案使用被否定的硬 Claim，以及同一天重复地点造成的折返。
4. 按 35% 可执行性、25% 偏好、20% 预算、10% 风险、10% 证据质量保存 `ScoreBreakdown`；Evidence 覆盖率按实际引用重算。
5. 事实/证据问题路由 A1，路线/交通问题路由 A2，排程/预算/折返问题路由 A3。
6. 每个唯一错误码生成一条 `PatchRequest`。A4 不改 Claim、Evidence 或计划；无错才 `PASS`，需返工则 `REVISE`。

`tests/test_critic_risk_agent.py` 覆盖合法通过、预设闭馆、超预算、折返、缺 Evidence、返工路由，以及 ScriptedModel + `schedule.validate` Fixture Tool。

## 8. 为什么有 Agent 外壳和确定性核心

A1/A2 以事实查询为主，正确性由工具边界和 Artifact Schema 保证。A3/A4 涉及硬约束，采用两层：

```text
BaseAgent（有限模型/工具循环）
  -> ToolGateway allowlist + Schema
    -> DeterministicItineraryOptimizer / DeterministicCritic
      -> Domain validators
```

模型可提出工具调用或组织解释，但不能绕过求解器和校验器。ScriptedModel 测试证明 Agent 外壳可独立运行，确定性核心测试证明没有模型/API Key 时关键规则仍可复现。
