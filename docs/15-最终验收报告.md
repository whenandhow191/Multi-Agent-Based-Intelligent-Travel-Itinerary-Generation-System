## 3. 安全与隐私验收

- Key、Token、Prompt 和原始 Provider 响应不会进入结构化遥测。
- Agent 工具权限由固定 allowlist 强制，Prompt Injection 不能授权新工具。
- 外部 URL 必须命中精确 HTTPS allowlist，且每次重定向重新校验。
- 匿名 Run Token 仅保存摘要；错误 Token 与不存在 Run 都返回 404。
- 删除 Run 同时删除结果、事件、版本和幂等映射。
- Fixture、Benchmark 和报告均为合成数据，不标成实时库存/价格。

## 4. 已知边界

- 当前产品 Run Service 是内存 Fixture 组合根；生产 Worker 应装配 C16/C23 的 PostgreSQL Repository/Blackboard。
- 前端地图当前是 GCJ-02 坐标示意；接入高德 JS SDK 时必须使用独立浏览器 Key。
- 真实 Provider 的质量、价格和配额会变化；上线前应使用获准数据重新执行 C38/C48。
- OpenTelemetry 默认提供 SDK 和手工埋点；具体 OTLP Collector 地址由部署环境配置，不写死在仓库。

## 5. 发布结论

代码级闸门、演示与 Compose 配置已通过。本机镜像构建失败原因是 Docker Desktop 指向未运行的本地代理 `127.0.0.1:7897`，不是 Dockerfile 或应用构建错误；Tag 推送后由无该本机代理的 GitHub Release 工作流重新构建。GitHub CI/Release 成功且 Tag 指向发布提交后，本项目满足教学路线 C00～C49 的 `v1.0.0` 验收标准。
