## 1. 本章交付结果

第九章把前八章的功能交付升级为可观测、可安全测试、可压测、可比较和可发布的完整系统。所有验收都可在 Fixture 模式离线执行；真实模型、地图和天气 Key 只是可选运行配置，不是测试前提。

## 2. C45：端到端遥测

提交：`feat(obs): add end-to-end telemetry`

主要文件：

- `packages/observability/telemetry.py`：OpenTelemetry Recorder、Model/Tool Gateway 包装器、结构化日志和 Claim lineage。
- `tests/test_observability.py`：使用 SDK 内存导出器验证真实 span。

`InstrumentedModelGateway` 和 `InstrumentedToolGateway` 是装饰器，不改变原 Gateway 的 Schema、allowlist 或异常语义。span 只记录：

- `run_id`、`task_id`、`agent_id`；
- 模型别名/响应模型或工具名；
- 输入/输出 Token、估算成本和延迟；
- 成功/失败与异常类型。

Prompt、模型原始响应、chain-of-thought、API Key 和匿名 Run Token 不进入 span。`SafeJsonFormatter` 还会按字段名递归隐藏 credential、key、password、prompt、secret、token 等字段。

`LineageIndex.trace_claim(claim_id)` 返回 `trace_id -> task -> Agent -> Artifact -> tools`，因此可从最终事实反查生产路径。

## 3. C46：集成与安全套件

提交：`test: add integration and security suites`

主要文件：

- `packages/security/boundaries.py`：不可信内容、SSRF URL allowlist 和自由文本密钥脱敏。
- `tests/test_integration_security.py`：E2E、契约、安全和数据删除。

外部网页/POI/用户粘贴内容由 `wrap_untrusted_content` 包装成明确的 `<untrusted-data>` 数据块，并标记常见注入信号。信号检测只用于风险观察；即使模型响应要求调用 `admin.delete`，固定 ToolGateway allowlist 仍会确定性拒绝。

`OutboundUrlPolicy` 要求 HTTPS、精确主机 allowlist、允许端口，不接受 URL 用户信息和直接 IP，并对每个重定向目标重新校验。这样 localhost、云元数据地址、恶意重定向和非常规端口都会在发出请求前失败。

API 契约测试还验证：未知字段返回 422；匿名令牌越权不泄露 Run 是否存在；删除后 Run、结果、事件和版本全部返回 404。

## 4. C47：韧性与性能

提交：`test: add resilience and performance suites`

`packages/evals/resilience.py` 在硬并发上限与单探针超时内运行场景，输出 success、partial、failure 和 P95。它不会自动无限重试。

本步同时修复 `InMemoryTripRunService.create` 的并发窗口：64 个线程使用同一个幂等键时，通过 `RLock` 只会产生一个 Run。测试还覆盖：

- 并发上限不超过 4；
- 单 Worker 崩溃不影响其他结果；
- Provider 超时被分类为 failure；
- 主 Provider 故障、Fallback 成功时显式返回 partial；
- 既有 heartbeat/checkpoint/Outbox 恢复和有限模型路由继续回归。

## 5. C48：单 Agent 与 1+4 对照

提交：`test: evaluate single versus multi agent workflow`

数据与代码：

- `benchmarks/workflow_comparison.jsonl`：20 条跨预算、天气、路线、证据、开放时间、供应商故障和局部重规划场景。
- `packages/evals/workflow_comparison.py`：同集评测与发布闸门。
- `benchmarks/workflow_comparison_report.md`：可复现报告。

指标为 Schema 通过率、硬约束通过率、引用覆盖、任务成功、平均延迟和平均成本。Fixture 基线结果：

| 工作流 | Schema | 硬约束 | 引用 | 成功 | 延迟 ms | 成本微单位 | 闸门 |
|---|---:|---:|---:|---:|---:|---:|---|
| 单 Agent | 90% | 80% | 75% | 80% | 480 | 85 | FAIL |
| 1+4 | 100% | 100% | 100% | 100% | 760 | 145 | PASS |

这是评测管线的合成基准，不是云模型性能承诺。它明确展示 1+4 用更高延迟和成本换取约束、引用和成功率，发布以绝对质量阈值为准。

## 7. 复现命令

```powershell
conda activate .\.conda\env
uv sync --active --all-groups --frozen
pnpm install --frozen-lockfile
pnpm check
pnpm demo
docker compose config --quiet
docker compose up --build
```

浏览器访问 `http://localhost:5173`，OpenAPI 访问 `http://localhost:8000/docs`。默认 Fixture 无需 Key。

## 8. 安全结论

- 不把用户截图中的 Key、`.env` 或配置值写入源码、测试、日志、文档、Commit 或 Tag。
- 高德 Web Service Key 只在服务端读取；浏览器地图 Key 必须是独立的最小权限 Key 并配置域名 allowlist。
- 已在聊天截图中出现过的 Key 应在高德控制台轮换后再用于长期部署。
- `docker compose down --volumes` 会删除本地数据库卷，普通停止只使用 `docker compose down`。
