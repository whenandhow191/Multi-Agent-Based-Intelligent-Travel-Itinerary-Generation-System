# 第六章实现说明：真实工具与数据源逐个接入

> 对应检查点：C27～C33  
> 完成日期：2026-09-13

## 1. 本章完成结果

本章把外部数据接入限制在 `packages/tools`，Agent 只看到稳定的内部工具名和领域模型。
已经完成高德地理编码、POI、路线，Open-Meteo 天气，非实时航班/铁路/酒店骨架，
以及统一 CLI 和可选 MCP 传输。没有把供应商原始 JSON、密钥或测试数据泄漏给业务层。

调用关系如下：

```text
Agent / travelctl / 后续 REST
              │
         ToolGateway（allowlist + 输入/输出 Schema）
              │
       packages/tools 供应商归一化层
        ├─ HTTP：高德、Open-Meteo
        ├─ Fixture：离线与失败降级
        └─ MCP：stdio / Streamable HTTP（可选）
```

## 2. C27：通用 HTTP Provider

主要文件：

- `packages/tools/http_provider.py`：统一 HTTP 客户端。
- `tests/test_http_provider.py`：模拟 200、429、500、超时和熔断。

实现顺序：请求先经过缓存和每秒请求数限制，再执行带超时的 HTTP 调用；429、5xx 和网络错误
按照有上限的指数退避重试，连续失败后开启熔断。审计记录只含请求哈希、状态、耗时、尝试次数和
缓存命中等元数据。响应只有在 `StoragePolicy` 明确允许时才按字段白名单保存。

对应提交：`feat(tools): add resilient provider client`。

## 3. C28：高德地理编码与 POI

主要文件：

- `packages/tools/amap.py`：`maps.geocode` 与 `places.search`。
- `tests/test_amap.py`：Fixture 和模拟真实响应的归一化测试。

适配器从 `Settings.amap_web_service_key` 取得 `SecretStr`，只在发起请求时解包，不写日志、
Artifact 或 Evidence。真实响应被转换为内部 `Place`、`Coordinate`、`Evidence`；坐标明确标记
为 GCJ-02。无 Key 时自动使用合成 Fixture，价格保持 unknown，游玩时长明确标记为系统估算。

接口依据高德官方 Web 服务文档：

- [地理编码 API](https://lbs.amap.com/api/webservice/guide/api/georegeo)
- [搜索 POI 2.0](https://lbs.amap.com/api/webservice/guide/api-advanced/newpoisearch)

对应提交：`feat(tools): integrate amap geocoding and poi`。

## 4. C29：路线、矩阵与坐标

主要文件：

- `packages/tools/routes.py`：`routes.compute`、`routes.matrix`、polyline 和坐标转换。
- `tests/test_routes.py`：受限矩阵、真实响应归一化与坐标转换测试。

路线矩阵不请求无限 NxN 数据，而是先构造定向候选对，再由 `max_pairs` 截断，适合 Planner
选出的 Top-K 点位。真实路线被归一化为内部 `Route`，地图展示只消费内部 `MapPolyline`。
WGS84 和 BD-09 会显式转换为 GCJ-02，避免把不同坐标系混用。

接口依据高德官方[路径规划 2.0](https://lbs.amap.com/api/webservice/guide/api/newroute)。

对应提交：`feat(tools): integrate routes and coordinate handling`。

## 5. C30：天气 Provider

主要文件：

- `packages/tools/weather.py`：`weather.forecast`。
- `tests/test_weather.py`：正常预报、远期日期和 Provider 失败三条路径。

选择无需 Key 的 Open-Meteo 作为默认天气源。请求日期在精确预报范围内时归一化每日天气；
超出范围时不伪造精确天气，只返回 `climate_guidance`；网络或 Provider 失败才返回带明确警告的
Fixture。接口依据 [Open-Meteo Forecast API](https://open-meteo.com/en/docs)。

对应提交：`feat(tools): integrate weather provider`。

## 6. C31：航班、铁路和酒店骨架

主要文件：

- `packages/tools/travel_stubs.py`：`flight.search`、`rail.official_link`、`lodging.search`。
- `tests/test_travel_stubs.py`：非实时标记、未知价格和官方链接测试。

没有商业数据权限时，航班和酒店仅提供 `fixture/manual` 模式并固定
`inventory_live=false`；费用使用 unknown，结果要求人工确认。铁路只生成
[中国铁路 12306](https://www.12306.cn/) 官方站点跳转，不抓取、不登录、不代购。
将来接入持牌 Provider 时只需实现对应 Protocol，A2 的内部契约不变。

对应提交：`feat(tools): add transport and lodging provider stubs`。

## 7. C32：统一 travelctl

主要文件：

- `packages/tools/registry.py`：装配 REST 与 Fixture 工具。
- `apps/api/travelctl.py`：CLI 适配器。
- `tests/test_travelctl.py`：发现、调用与非法参数测试。

常用命令：

```powershell
python -m apps.api.travelctl doctor
python -m apps.api.travelctl tools list
python -m apps.api.travelctl tools call fixture.echo --arguments '{"message":"hello"}'
python -m apps.api.travelctl run inspect run_001
python -m apps.api.travelctl blackboard get --run-id run_001 --task-id task_001 --type review --version 1
```

`tools call` 并不绕过内核，而是构造审计上下文后调用 `ToolGateway.execute`。数据库命令使用
SQLAlchemy 参数化查询；整个 CLI 没有 `shell=True` 或命令字符串拼接。

对应提交：`feat(cli): add travelctl and cli adapter`。

## 8. C33：可选 MCP 传输

主要文件：

- `packages/tools/mcp_adapter.py`：stdio、Streamable HTTP、发现和包装。
- `tests/test_mcp_adapter.py`：allowlist、Schema、名称映射、JSON/SSE 与会话头测试。

适配器先执行 `initialize` 和 `notifications/initialized`，再调用 `tools/list`。只有配置在
allowlist 中的远端工具会被暴露；名称统一映射为 `mcp.<server>_<tool>`，发现时的输入 Schema
会复制为快照并转成 Pydantic 模型。调用仍经过本地 ToolGateway 校验。stdio 使用固定 argv 的
`create_subprocess_exec`，不启动 shell；HTTP 同时接受 JSON 和 SSE，保存服务端会话 ID，并对
连接超时与响应大小设硬上限。

实现遵循 MCP 稳定版 2025-06-18 的
[生命周期](https://modelcontextprotocol.io/specification/2025-06-18/basic/lifecycle)、
[传输](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)和
[工具](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)规范。

对应提交：`feat(tools): add optional mcp transport`。

## 9. 高德 Key 的正确配置方式

仓库只保存 `.env.example` 中的变量名，真实值必须放在已被 Git 忽略的 `.env.local`：

```dotenv
AMAP_WEB_SERVICE_KEY=替换为新生成的Web服务Key
```

然后只检查“是否存在”，不要打印值：

```powershell
python -m apps.api.travelctl doctor
```

若输出 `AMAP_WEB_SERVICE_KEY: present (optional)`，说明配置层已读取。截图、聊天消息、Issue、
提交和测试 Fixture 都不能包含真实 Key。当前对话截图已经展示过一枚完整 Key，应立即在高德
控制台删除或停用它并新建 Key；本次实现没有复制或提交该值。轮换后再把新值只写入本机
`.env.local`。

## 10. 完整复验

在项目专用 Conda 环境中执行：

```powershell
.\.conda\env\python.exe -m ruff format --check .
.\.conda\env\python.exe -m ruff check .
.\.conda\env\python.exe -m mypy
.\.conda\env\python.exe -m pytest
```

所有 Provider 测试使用本地 MockTransport 或合成 Fixture，不消耗外部额度，也不会把真实响应
固化为测试数据。需要真实冒烟测试时，先轮换泄漏的 Key，再使用 `travelctl tools call` 发起一条
最小查询，并确认返回 `provider_mode=live`。
