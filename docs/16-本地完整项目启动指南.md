# 本地完整项目启动指南

> 适用系统：Windows 10/11 + PowerShell  
> 推荐方式：Docker Compose  
> 项目目录：`D:\学习资源\Agent项目\基于多Agent的智能旅游攻略生成系统`

## 1. 最短启动步骤

先确认 Docker Desktop 已经启动，然后打开 PowerShell，执行：

```powershell
Set-Location -LiteralPath 'D:\学习资源\Agent项目\基于多Agent的智能旅游攻略生成系统'
docker compose --env-file .env.local up --build
```

这两条命令的目的分别是：

1. `Set-Location`：进入包含 `compose.yaml`、`.env.local`、前后端源码的项目根目录。
2. `docker compose --env-file .env.local up --build`：读取本机配置，构建镜像并启动数据库、数据库迁移、FastAPI 后端和 React 前端。

首次构建需要下载基础镜像和安装依赖，耗时会比后续启动长。终端需要保持打开；看到
`db`、`api` 和 `web` 健康运行后即可访问页面。

## 2. 启动前检查

### 2.1 Docker Desktop

运行：

```powershell
docker info
```

如果能输出 Server 信息，说明 Docker 引擎可用。如果提示无法连接 daemon，应先启动
Docker Desktop，等待界面显示引擎已经运行。

### 2.2 PenguinAPI 配置

密钥文件必须位于项目根目录：

```text
D:\学习资源\Agent项目\基于多Agent的智能旅游攻略生成系统\.env.local
```

内容应包含：

```dotenv
PENGUIN_API_KEY=你的真实Key
PENGUIN_BASE_URL=https://api2.penguinsaichat.dpdns.org/v1
```

不要给 Key 加多余引号或尾部空格。`.env.local` 已被 Git 忽略，Docker Compose 只会把
它注入 API 容器，不会注入 Web 容器或发送给浏览器。

可以执行以下命令检查 Compose 配置语法；它不会打印密钥值：

```powershell
docker compose --env-file .env.local config --quiet
```

命令没有输出且退出码为 0，表示配置合法。

## 3. 四个 Compose 服务分别做什么

| 服务 | 作用 | 正常状态 |
|---|---|---|
| `db` | 启动 PostgreSQL 16，保存运行、任务、Artifact 等持久数据 | `healthy` |
| `migrate` | 在 API 启动前执行 Alembic 数据库迁移 | 执行完后 `Exited (0)` |
| `api` | 启动 FastAPI、模型代理、运行 API 和 OpenAPI 页面 | `healthy` |
| `web` | 构建并通过 Nginx 提供 React 产品页面 | `healthy` |

`migrate` 正常退出不是故障。它是一次性任务，退出码 0 代表数据库结构已经升级成功。

## 4. 判断是否启动成功

新开一个 PowerShell，仍然在项目根目录运行：

```powershell
docker compose ps
```

预期结果：

- `db`：Up / healthy；
- `api`：Up / healthy；
- `web`：Up / healthy；
- `migrate`：Exited (0)，或者不再显示在默认运行列表中。

也可以检查 API：

```powershell
Invoke-RestMethod http://localhost:8000/health
```

预期返回：

```text
status service    version
------ -------    -------
ok     travel-api 1.0.0
```

## 5. 浏览器访问地址

| 地址 | 用途 |
|---|---|
| `http://localhost:5173` | 产品前端，填写旅行需求、选择模型、查看结果 |
| `http://localhost:8000/docs` | FastAPI Swagger，可直接检查和调用后端接口 |
| `http://localhost:8000/health` | API 存活检查 |
| `http://localhost:8000/api/v1/models` | 后端返回的 Penguin 模型目录与连接状态 |

## 6. 在前端验证 Penguin 模型

1. 打开 `http://localhost:5173`。
2. 在“运行模型”下拉框选择模型。
3. 点击“测试连接”。
4. 页面显示“连接成功，密钥不会发送到浏览器”后，说明：
   - API 容器读取到了 `.env.local`；
   - Key 通过中转站鉴权；
   - 所选模型可通过 Anthropic-compatible `/v1/messages` 返回结构化 JSON。
5. 填写旅行需求并点击“生成旅行方案”。

可选模型白名单为：

- `claude-sonnet-5`
- `claude-opus-5`
- `gpt-5.6-luna`
- `gpt-5.6-sol`
- `gpt-5.6-terra`

连接测试是一次真实、极小的模型调用，可能产生少量中转站费用。

当前产品的行程结果仍明确使用 Fixture 合成流程；模型选择会随 Run 保存，但还没有冒充
完整实时 1+4 Agent 生成结果。完整实时模型工作流需要在模型协议、工具调用和成本限制
通过连接验收后再启用。

## 7. 常用运行命令

以下命令都应在项目根目录运行。

### 前台启动并查看全部日志

```powershell
docker compose --env-file .env.local up --build
```

适合第一次启动或排查问题。按 `Ctrl+C` 停止前台进程。

### 后台启动

```powershell
docker compose --env-file .env.local up --build -d
```

适合日常使用，关闭 PowerShell 后服务仍继续运行。

### 查看服务状态

```powershell
docker compose ps
```

### 查看 API 日志

```powershell
docker compose logs --tail 200 -f api
```

`-f` 表示持续跟踪；按 `Ctrl+C` 退出日志查看，不会停止容器。

### 查看前端日志

```powershell
docker compose logs --tail 200 -f web
```

### 在 API 容器内检查密钥是否存在

```powershell
docker compose exec api python -m apps.api.config doctor
```

预期包含：

```text
PENGUIN_API_KEY: present (optional)
```

该命令只显示 `present/missing`，不会回显真实 Key。

### 停止项目

```powershell
docker compose down
```

这会停止并删除项目容器和网络，但保留 PostgreSQL 数据卷。

### 清空数据库并重新开始

```powershell
docker compose down --volumes
```

这会删除 PostgreSQL 数据卷，历史运行数据无法恢复。只有明确需要重置全部本地数据时才
使用，不能把它作为普通停止命令。

## 8. 修改配置后的重启方法

只修改 `.env.local` 后，重新创建 API 容器即可：

```powershell
docker compose --env-file .env.local up -d --force-recreate api
```

修改 Python、React、依赖或 Dockerfile 后，应重新构建：

```powershell
docker compose --env-file .env.local up --build -d
```

## 9. 可选：源码热更新开发模式

完整体验优先使用 Docker Compose。需要调试源码时，可以只让 Docker 运行数据库，然后
在两个 PowerShell 中分别运行前后端。

终端一，在项目根目录运行数据库和迁移：

```powershell
docker compose up -d db
docker compose run --rm migrate
conda activate .\.conda\env
python -m uvicorn apps.api.main:app --reload --host 0.0.0.0 --port 8000
```

终端二，在同一项目根目录运行前端：

```powershell
pnpm --dir apps/web dev
```

这种模式的目的，是让 Python 和 React 修改后自动刷新；PostgreSQL 仍由 Docker 隔离运行。

## 10. 常见问题

### `docker` 不是可识别的命令

Docker Desktop 尚未安装，或安装后当前终端没有刷新 PATH。安装/启动 Docker Desktop，
关闭并重新打开 PowerShell。

### `Cannot connect to the Docker daemon`

Docker Desktop 尚未完全启动。等待引擎运行后再次执行 `docker info`。

### 端口 5173、8000 或 5432 被占用

在 `.env.local` 增加不同端口，例如：

```dotenv
WEB_PORT=5174
API_PORT=8001
POSTGRES_PORT=5433
```

如果修改 API 端口，还应让前端构建使用对应地址：

```dotenv
VITE_API_BASE_URL=http://localhost:8001
```

然后执行 `docker compose --env-file .env.local up --build -d`，并访问新的 Web 端口。

### 模型列表显示未配置

依次检查：

```powershell
docker compose exec api python -m apps.api.config doctor
docker compose logs --tail 200 api
```

如果 `PENGUIN_API_KEY` 显示 `missing`，确认文件名是 `.env.local`，且文件位于项目根目录，
随后执行 `docker compose --env-file .env.local up -d --force-recreate api`。

### 模型连接返回 401

Key 无效、被撤销，或没有当前模型的权限。重新检查中转站令牌状态、余额和模型授权。

### 模型连接返回 429

中转站限流或余额/并发额度不足。稍后重试，并检查账号配额。

### 前端能打开但 API 离线

运行：

```powershell
docker compose ps
docker compose logs --tail 200 api
```

重点查看数据库迁移、端口、`.env.local` 格式和 API 启动错误。

## 11. 推荐的日常使用顺序

```powershell
Set-Location -LiteralPath 'D:\学习资源\Agent项目\基于多Agent的智能旅游攻略生成系统'
docker compose --env-file .env.local up -d
docker compose ps
```

随后打开 `http://localhost:5173`。使用结束后执行：

```powershell

```
