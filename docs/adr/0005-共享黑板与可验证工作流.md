# ADR-0005：共享黑板与可验证工作流

- 状态：Accepted
- 日期：2026-09-13
- 决策者：项目维护者
- 关联检查点：C23～C26

## 背景

1+4 Agent 需要共享大体积结构化结果、支持多个 Worker 并发、局部返工和完整来源追踪。直接传递可变 Python 对象或完整对话无法持久恢复，也无法证明某个最终行程引用了哪一版事实。

## 决策

1. 大结果保存为不可变 `ArtifactRecord`，任务和 trace 只传 `ArtifactRef`。
2. 逻辑版本键为 `(run_id, task_id, artifact_type, version)`；内容使用 canonical JSON SHA-256 防篡改。
3. PostgreSQL 使用独立 `artifact_heads` 行锁串行化同一逻辑 Artifact 的版本推进，调用方同时提供期望版本。
4. 父子关系保存在 `artifact_parents`，lineage 不得跨 run。
5. A1/A2 用 `asyncio.gather()` 真并行；全量 Route Matrix 必须在 fan-in 后由 Harness 构造。
6. PatchRequest 通过显式依赖图传播失效，只重跑责任节点及其下游，最多两轮。
7. 人工问题进入 `WAITING_USER`，收到字段级答案后再选择受影响分支。
8. FinalAggregator 只接受 PASS Review，并独立重跑确定性校验；JSON 与 Markdown 来自同一个 `FinalPlanBundle`。

## 后果

正面后果：并发更新不会静默覆盖；每个最终字段可以追溯版本；酒店等局部变化不会重跑目的地研究；无最终润色模型也能稳定交付。

代价：需要维护 Artifact 版本和依赖图；lineage 表会持续增长；当前依赖图是 MVP 固定图，扩展 Agent 后必须同步更新失效规则。

GitHub Actions 在 PostgreSQL 16 service 上额外执行真实 Blackboard 并发写入用例。

## 复审条件

- 单个 run 的 Artifact 数量使 lineage 查询不可接受。
- 工作流从固定 DAG 演进为用户定义动态图。
- 需要跨区域多主写入或外部对象存储大 payload。
- 最终渲染增加多语言或可插拔模板，但仍必须保留同源校验。
