# ADR-0006：可观测、安全与发布闸门

- 状态：Accepted
- 日期：2026-09-21

## 背景

系统已经具备领域契约、1+4 Agent、共享 Blackboard、真实工具边界、模型治理和 Web 产品。正式发布前必须能从最终事实追溯执行路径，在不泄密的前提下定位故障，并以可复现的安全、韧性和质量证据决定是否发布。

## 决策

1. 使用 OpenTelemetry API/SDK 做供应商中立的手工埋点，在 ModelGateway 和 ToolGateway 外层装饰，不把遥测耦合进 Agent 业务代码。
2. 只记录低基数标识、延迟、Token、成本和状态；Prompt、chain-of-thought、密钥、匿名 Token 和原始响应禁止进入遥测。
3. Prompt Injection 检测只产生风险信号；确定性 Tool allowlist、URL allowlist 和 Schema 才是权限边界。
4. 发布必须通过格式、Lint、类型、测试、前端构建、无 Key 演示、Compose 校验和镜像构建。
5. 单 Agent 与 1+4 使用同一固定数据集比较，分别报告质量、延迟和成本；质量采用绝对阈值。
6. `v*` Tag 只在发布提交验证完成后创建，并由 GitHub Actions 生成不可变 Release。

## 后果

- 可以从 Claim 追到 Agent、Artifact 和工具调用，同时不保存敏感模型上下文。
- 安全与发布失败会在 CI 中阻断，不依赖人工记忆。
- 多 Agent 的额外成本被显式呈现，不能只用质量提升作为无条件采用的理由。
- 生产部署仍需选择并配置具体 OTLP Collector、Secret 管理和 PostgreSQL 备份方案。
