# ADR-0004：1+4 Agent 职责与确定性边界

- 状态：Accepted
- 日期：2026-09-13
- 决策者：项目维护者
- 关联检查点：C18～C22

## 背景

系统需要让 Coordinator、目的地、交通住宿、规划与审校协作。如果它们直接互调、共享可变上下文或都能访问所有工具，就无法解释事实来源、约束由谁执行，也难以定位错误属于模型逻辑还是外部数据。

## 决策

1. Coordinator 只输出固定白名单任务图、澄清决策和预算，不执行调度、不调用业务工具、不生成旅行事实。
2. Harness 是任务状态、依赖、并发、重试、超时、候选合并和全量 Route 矩阵的唯一所有者。
3. A1 只拥有目的地事实；A2 只拥有交通住宿事实及已有端点定向路线；二者不能互调。
4. A3 不访问开放互联网。模型只可申请确定性规划工具，硬约束最终由 OR-Tools 与领域校验器执行。
5. A4 只审校并输出 `HardViolation`/`PatchRequest`，不能直接改写 Claim、Evidence 或候选方案。
6. 四个业务 Agent 都使用独立 allowlist、结构化输出 Schema、步骤/调用/超时上限。
7. Agent 之间只传版本化 Artifact/引用；未知值、供应商失败和冲突必须保留，不能填成确定事实。

## 后果

正面后果：每个 Agent 能用 ScriptedModel 与 Fixture Tool 独立验收；事实、优化与审校责任清晰；真实 Provider 接入前即可离线发现编排和契约错误；硬约束不依赖语言模型自觉遵守。

代价：需要维护更多显式 Artifact 和适配代码；A1/A2 合并与 Route 矩阵会增加一个 Harness 阶段；模型不能直接“顺手修复”跨领域问题，必须走 PatchRequest 和有限返工。

## 复审条件

- Agent 数量或工作流类型增长到固定白名单 DAG 难以维护。
- 引入新的优化后端，或多城市、多日复杂预约需要拆分求解器。
- 实际评测证明 A4 的确定性规则不足以覆盖语义矛盾。
- Tool 权限需要按租户、地区或数据许可动态生成。
