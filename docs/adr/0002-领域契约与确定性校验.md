# ADR-0002：领域契约与确定性校验

- 状态：Accepted
- 日期：2026-09-12
- 决策者：项目维护者
- 关联检查点：C06～C11

## 背景

旅行规划会同时接收用户自然语言、多个供应商数据和模型生成结果。若这些对象直接以任意字典流转，字段拼写、金额精度、坐标系、状态值和来源引用都可能在运行后期才暴露问题；预算、时间和闭馆判断也不能交给模型概率性决定。

## 决策驱动因素

- 同一契约可供 API、Harness、Agent、Tool Adapter 和前端边界复用。
- 金额、时间、坐标系和引用必须能被程序重新计算与审计。
- 无网络、无外部 Key 时可以稳定测试全部规则。
- 供应商原始字段不会扩散到领域层。
- 未知数据不能被静默当作零、可用或已验证。

## 考虑过的方案

### 任意字典加提示词约束

实现快，但字段漂移只能在运行时人工发现，模型也无法保证每次遵守金额、日期和引用规则。

### 为每个供应商建立一套业务模型

能保留供应商细节，但 Planner 和 Critic 会依赖多个不一致结构，更换 Provider 时需要改写业务逻辑。

### 供应商中立 Pydantic 契约加纯函数校验（采用）

Tool Adapter 负责转换，领域对象拒绝额外字段并保持不可变；跨对象规则由确定性纯函数检查，模型只负责适合语言理解与候选生成的部分。

## 决策

1. 所有领域对象继承严格、不可变的 `DomainModel`，使用明确枚举、范围和时区感知时间。
2. 金额使用 `Decimal` 和 `CostEstimate`，并区分已知、范围与未知；未知值不当作零。
3. 坐标必须携带 `WGS84`、`GCJ02` 或 `BD09`，内部规划前统一为一个显式 canonical system。
4. 事实使用 `Claim`，来源使用 `Evidence`，所有跨对象关系只通过稳定 ID 引用。
5. `PlanCandidatesArtifact`、`ReviewArtifact` 和 `FinalPlanBundle` 是 Agent/最终输出的版本化边界。
6. 预算、时间窗、重叠、开放时间、坐标系和引用完整性由 `validators.py` 的纯函数校验；报告使用稳定错误码，不依赖展示文本。
7. 合成 Fixture 和 `ScriptedModel` 不读网络、环境密钥或真实用户数据，并使用固定时间、ID 和数值保证重放一致。

## 后果

正面后果：错误更早暴露，测试可重复，供应商替换被限制在 Tool Adapter，Critic 与最终聚合器可共享硬校验结果。

代价：新增字段需要同步更新模型、示例、Fixture、测试和代码地图；跨对象约束不能只依赖单个 Pydantic 模型，需要显式传入完整上下文。

## 复审条件

- 领域契约需要跨语言发布，Pydantic 不再是唯一 schema 源。
- 坐标转换、跨夜开放时间或多币种结算进入 MVP。
- Fixture 规模需要专用数据版本管理或许可审计系统。
- 校验规则需要配置化、增量执行或解释性规则引擎。
