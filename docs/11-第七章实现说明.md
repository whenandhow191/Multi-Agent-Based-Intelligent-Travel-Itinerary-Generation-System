# 第七章实现说明：模型配置、成本与评测

> 对应检查点：C34～C38  
> 完成日期：2026-09-13  
> 默认策略：DeepSeek V4.1 Flash；高级策略：按 Agent 切换 GPT

## 1. 本章完成结果

本章把模型从 Agent 业务代码中完全拆开。Agent 只依赖统一的 `ModelGateway`，具体供应商、模型、推理强度、输出上限和超时由 YAML 决定。默认档统一使用 DeepSeek V4.1 Flash；需要更高能力时进入 GPT 高级档，Coordinator 还可进入旗舰档。

需要特别区分“产品名称”和“请求 ID”：DeepSeek 将产品称为 **DeepSeek V4.1 Flash**，当前 Responses API 的正式模型 ID 是 `deepseek-flash`。`deepseek-v4-flash` 只是官方公告中说明的临时兼容入口，因此仓库统一使用 `deepseek-flash`，避免把短期别名写成架构依赖。

## 2. 运行时调用链

```text
Agent
  -> ModelGateway（供应商中立契约）
  -> RoutedModelGateway（失败分类、有限重试、换档）
  -> BudgetedModelGateway（Token/工具费记账、预算闸门）
  -> ProfiledModelGateway（应用该 Agent 的 YAML 参数）
  -> Responses/OpenAI-compatible/Ollama Adapter
  -> DeepSeek、OpenAI 或本地 Ollama
```

每一层只承担一种职责，因而替换模型不需要修改四个专家 Agent 或 Coordinator 的代码。

## 3. C34：Provider Adapter

建议提交：`feat(models): add provider adapters`

主要文件：

- `packages/harness/model_gateway.py`：补全供应商中立的推理强度、结构化请求与统一 Usage 契约。
- `packages/models/adapters.py`：实现 Responses API、OpenAI-compatible Chat Completions 和 Ollama 三种适配器。
- `packages/models/__init__.py`：集中导出模型层公共 API。
- `packages/models/README.md`：声明 Agent 不得直接依赖供应商 SDK、Key 不得进入日志的边界。
- `tests/test_model_adapters.py`：使用 `httpx.MockTransport` 离线验证结构化输出、工具调用名称映射和 Usage 归一化。

适配器把供应商返回统一成 `ModelTurn`，并把 429、超时、余额、鉴权、Schema、服务端和网络故障统一分类为 `ModelProviderError`。工具名在外部 API 不允许句点时会编码，返回后再恢复内部名称。

## 4. C35：每个 Agent 的模型档位

建议提交：`feat(models): add per-agent model profiles`

主要文件：

- `config/providers.yaml`：供应商端点、Adapter 类型、默认模型和密钥环境变量名。
- `config/agents.yaml`：1+4 Agent 的 provider/model/reasoning/max tokens/timeout。
- `packages/models/profiles.py`：严格校验 YAML、解析档位并构建 Gateway。
- `apps/api/settings.py`、`apps/api/config.py`：加载 DeepSeek/OpenAI/Ollama 配置并以脱敏方式诊断。
- `.env.example`、`compose.yaml`：给出变量名并把服务器端 Key 安全传入 API 容器。
- `tests/test_model_profiles.py`、`tests/test_settings.py`：验证配置换模与密钥不泄漏。

当前模型矩阵：

| Agent | 默认档 | 高级档 | 旗舰档 | 选型意图 |
|---|---|---|---|---|
| A0 Coordinator | DeepSeek `deepseek-flash` | OpenAI `gpt-5.6-sol` | OpenAI `gpt-6-astra` | 任务分解和全局决策优先保留更强升级路径 |
| A1 目的地情报 | DeepSeek `deepseek-flash` | OpenAI `gpt-5.6-luna` | — | 大量结构化整理，优先吞吐与成本 |
| A2 交通与住宿 | DeepSeek `deepseek-flash` | OpenAI `gpt-5.6-terra` | — | 需要稳健处理约束、失败和人工确认 |
| A3 行程规划 | DeepSeek `deepseek-flash` | OpenAI `gpt-5.6-terra` | — | 路线、预算与时间窗组合推理 |
| A4 审校与风险 | DeepSeek `deepseek-flash` | OpenAI `gpt-5.6-terra` | — | 需要严格发现矛盾并输出修复请求 |

“高级”不是在 Agent 源码中写 `if`，而是让组合根选择 `advanced` 档；以后更换 GPT 型号只改 YAML。

## 5. C36：成本账本与预算闸门

建议提交：`feat(models): add usage ledger and budget gates`

主要文件：

- `config/pricing.yaml`：可审计、可替换的单价快照，金额使用美元微单位整数，避免浮点误差。
- `packages/models/ledger.py`：记录输入、缓存输入、输出、推理 Token、工具费和总成本。
- `packages/harness/model_gateway.py`、`packages/harness/agent.py`：把预算状态传播到模型结果和 Agent 结果。
- `tests/test_usage_ledger.py`：验证缓存计价、工具费与 run/agent/day 三层预算。

预算不是只记录日志。任一硬上限被超过后，结果显式返回 `partial` 和被超过的 scope；调用方可以保留已有结果，同时停止继续烧钱。`pricing.yaml` 是带日期语义的运维配置，不是永远正确的价格事实，上线前应按供应商计费页更新。

## 6. C37：有限重试、Fallback 与升级

建议提交：`feat(models): add fallback and escalation policies`

主要文件：

- `packages/models/routing.py`：候选模型、失败策略、有限重试与路由审计。
- `packages/models/profiles.py`：从 default → advanced → flagship 构造候选链。
- `packages/harness/model_gateway.py`：在结果中保存每次尝试、最终模型、是否 fallback/升级以及 Brain 是否降级。
- `tests/test_model_routing.py`：模拟 429、Schema 失败、Coordinator 降级和总尝试上限。

处理规则：

- 429、超时、5xx、网络错误：在当前候选上做有限指数退避，然后换下一个候选。
- 余额不足、鉴权失败、Schema 失败：当前候选重试通常无意义，直接切换。
- 所有候选和总尝试次数都有硬上限，禁止无限循环。
- Coordinator 如果被迫使用更低档模型，结果必须带 `brain_downgraded=true`，不能静默降低总控质量。

## 7. C38：25 条分 Agent 基准集

建议提交：`test(models): benchmark agent model candidates`

主要文件：

- `benchmarks/model_cases.jsonl`：25 条纯合成用例，Coordinator、A1、A2、A3、A4 各 5 条。
- `benchmarks/README.md`：数据安全和分组评测要求。
- `packages/evals/model_benchmark.py`：运行候选模型并生成结构化报告和 Markdown 表格。
- `packages/evals/__init__.py`：导出基准评测公共 API。
- `tests/test_model_benchmark.py`：验证样本规模、分组、指标和报告。

每个 Agent、每个候选模型单独统计：

- 输出 Schema 通过率；
- 硬约束通过率；
- 引用/证据通过率；
- 成功率；
- 平均延迟；
- 每个成功结果的平均成本。

这避免用一个总平均掩盖某个 Agent 的失败。25 条数据适合本章建立机制，但不是生产级结论；接入真实模型后应在脱敏前提下扩充边界案例并固定模型版本重新评测。

## 8. API Key 配置

本章的 Fixture、MockTransport 和单元测试不需要任何 Key。真实调用按所选档位需要：

1. 在项目根目录复制 `.env.example` 为 `.env.local`。
2. 默认 DeepSeek 档填写 `DEEPSEEK_API_KEY`。
3. 需要 GPT 高级/旗舰档时再填写 `OPENAI_API_KEY`。
4. 本地 Ollama 不需要 Key，只需确认 `OLLAMA_BASE_URL`。
5. 运行 `python -m apps.api.config doctor`，它只显示 `present/missing`，绝不回显密钥。

示例仅写变量名，不要把真实值提交到 Git：

```dotenv
DEEPSEEK_API_KEY=<只写在本机 .env.local>
OPENAI_API_KEY=<需要高级 GPT 时再填写>
```

不要在聊天、Issue、日志或截图里发送完整 Key。若希望我继续联调，只需告诉我“已在 `.env.local` 配好 DeepSeek/OpenAI Key”，我会通过 `doctor` 和实际最小调用验证，既不读取也不回显密钥内容。

## 9. 验证与复现

在项目专用 Conda 环境中运行：

```powershell
conda activate .\.conda\env
python -m apps.api.config doctor
python -m pytest tests/test_model_adapters.py tests/test_model_profiles.py tests/test_usage_ledger.py tests/test_model_routing.py tests/test_model_benchmark.py
pnpm check
```

评测模块要求数据集为 20～50 条，并要求每个出现的 Agent 至少有 4 条用例；非法规模会在运行前失败。
