> 文档版本：v1.1（C15）
> 更新日期：2026-09-12  
> 适用检查点：C00～C15

## 1. 如何阅读本仓库

推荐按以下顺序理解项目：

1. `README.md`：先运行最小命令，确认本地环境可用。
2. `docs/01-需求规格说明书.md`：理解产品目标、边界和验收标准。
3. `docs/02-技术实现方案.md`：理解 1+4 Agent、自建 Harness 和供应商隔离方案。
4. `docs/03-教学式开发路线与Git交付计划.md`：了解 C00～C49 的学习顺序。
5. 本文：从路径定位到代码和配置。
6. `docs/adr/`：了解关键选择的背景、取舍和后果。

当前依赖方向为：

```text
apps/web  ──HTTP──>  apps/api  ──后续章节──>  packages/harness
                                  │                  │
                                  └──────────────>  packages/domain
                                                     │
packages/agents  ──后续通过 Harness 调用─────────────┤
packages/tools   ──后续归一化外部数据───────────────┘
packages/evals   ──测试整个系统，不被生产代码依赖
```

硬规则：领域层不得依赖应用层；Agent 不直接互调；前端不重新决定行程事实；供应商私有结构不得越过 Tool Gateway。

## 3. 应用代码

### 3.1 FastAPI：`apps/api`

| 路径 | 职责 | 依赖/输入 | 被谁调用 |
|---|---|---|---|
| `apps/__init__.py` | 标记可部署应用命名空间 | 无 | Python 导入系统 |
| `apps/api/__init__.py` | 标记 API 包 | `apps` | 测试、uvicorn |
| `apps/api/main.py` | 创建 FastAPI、装配 CORS、提供 `GET /health` | `settings.py`、FastAPI、Pydantic | uvicorn、Web、健康检查、测试 |
| `apps/api/settings.py` | 类型化配置、dotenv 分层、生产安全校验和缓存 | pydantic-settings、环境变量 | `main.py`、`config.py`、测试 |
| `apps/api/config.py` | 实现密钥安全的 `config doctor` | `settings.py` | 开发者、诊断脚本、测试 |
| `apps/api/Dockerfile` | 用锁文件构建 Python 3.12 API 镜像 | uv、`pyproject.toml`、API/Packages | Compose |
| `apps/api/README.md` | API 层职责和边界 | 设计文档 | 开发者 |

`/health` 是不依赖数据库和外部 Provider 的进程存活检查。数据库就绪由 Compose 的 PostgreSQL healthcheck 负责；真正的数据库连通性与迁移检查在后续数据库检查点实现。

## 4. 可复用包

本章只建立可导入边界，实际领域契约与 Harness 会从第二章起逐步进入。

| 路径 | 当前职责 | 未来主要消费者 |
|---|---|---|
| `packages/__init__.py` | 标记共享包命名空间 | 所有 Python 应用 |
| `packages/domain/common.py` | 不可变、禁止额外字段的 Pydantic 基类与公共标量 | 全部领域模型 |
| `packages/domain/trip_request.py` | TripRequest、预算、硬约束、软偏好与澄清问题 | API、Coordinator、Planner |
| `packages/domain/messaging.py` | Task/Event/ArtifactRef/Claim/Evidence 与状态枚举 | Harness、Agents、持久化层 |
| `packages/domain/travel.py` | POI、路线、天气、住宿、交通、费用和显式坐标系模型 | Tool Adapters、A1/A2、Planner |
| `packages/domain/itinerary.py` | PlanCandidates/Review/FinalPlanBundle 与对比、修复契约 | A3、A4、Aggregator、API/Web |
| `packages/domain/validators.py` | 预算、时间窗、重叠、开放时间、坐标系和跨对象引用的确定性校验 | Critic、Aggregator、API、Evals |
| `packages/domain/__init__.py` | 领域公共 API，集中导出稳定契约 | API、Harness、Agents、Tools |
| `packages/harness/model_gateway.py` | Provider-neutral 模型消息、工具、策略、Usage、请求/响应和 Gateway 协议 | Agents、模型适配器、Evals |
| `packages/harness/tool_gateway.py` | 工具注册、JSON Schema、allowlist、输入/输出校验和唯一执行入口 | Agents、Tool Adapters、CLI/MCP/API |
| `packages/harness/agent.py` | Agent 上下文、有限模型/工具循环、步骤/调用/超时限制、结构化输出与错误分类 | 所有业务 Agent、Scheduler |
| `packages/harness/scheduler.py` | DAG 合法性、就绪判断、并发执行、协作取消、超时与有限重试 | Worker、Coordinator、API |
| `packages/harness/` | 自建状态机、DAG、调度、策略和恢复的公共 API | API、Worker、Agents |
| `packages/agents/` | Coordinator 与四个专家 Agent | Harness |
| `packages/tools/` | Tool Gateway、注册表与 Provider Adapter | Harness、Agents |
| `packages/evals/fixtures.py` | 固定时间、ID、金额和引用关系的完整合成场景工厂 | 离线单元测试、演示 |
| `packages/evals/scripted_model.py` | 顺序返回预校验响应的无网络模型替身 | Harness/Agent 单元测试 |
| `packages/evals/` | 评测公共 API、数据集、运行器和质量/成本指标 | CI、评测命令 |

每个目录的 `__init__.py` 使空包可导入，`README.md` 说明职责与禁止跨越的边界。

## 7. 代码地图维护规则

- 每个检查点新增、删除或改变职责的源码文件，都必须同步更新本文。
- 只写稳定职责和依赖方向，不复制实现代码。
- 新的跨模块依赖必须符合本页依赖方向；例外要先写 ADR。
- 文件移动后同时更新 README、测试引用、Compose/CI 路径和本文。
