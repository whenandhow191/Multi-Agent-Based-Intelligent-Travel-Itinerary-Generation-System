# 第二章“领域契约与确定性基础”实现说明

> 对应开发路线：C06～C11  
> 完成日期：2026-09-12  
> 目标：说明领域契约、离线测试替身与确定性校验分别如何完成，并给出复现方式

## 1. 完成结果

第二章建立了后续 Harness、Agent、Tool Adapter 和 API 共同使用的稳定语言：

- 用户输入可转换为严格的 `TripRequest`，硬约束、软偏好和澄清问题彼此分离。
- Task/Event/Artifact/Claim/Evidence 有版本化消息契约和有限状态枚举。
- POI、路线、天气、住宿和交通先归一化，再进入规划层；金额与坐标系不会丢失语义。
- 候选方案、审校结果和最终攻略可以生成 JSON，并重新通过同一 Schema 校验。
- 完整合成场景与 `ScriptedModel` 在无网络、无 API Key 时产生固定响应。
- 预算、时间窗、活动重叠、开放时间、坐标系和引用完整性由程序确定性检查。

本次完成时，`pnpm check` 的实际结果为 Python 32 个测试通过、Web 1 个测试通过，Ruff、ESLint、mypy、TypeScript 和 Vite 生产构建全部通过。

核心数据流是：

```text
TripRequest
    │
    ├── Task / Event / ArtifactRef
    │
Provider data ──Adapter──> Place / Route / Weather / Lodging / Transport
    │                              │
    └── Evidence <── Claim ────────┤
                                   ▼
                 PlanCandidatesArtifact
                                   ▼
                       ReviewArtifact
                                   ▼
                       FinalPlanBundle
                                   ▼
                  deterministic validators
```

## 3. C06：旅行请求契约

提交信息：`feat(domain): define trip request contracts`

`packages/domain/trip_request.py` 完成以下层次：

- `TravelParty` 计算同行人数并限制人数范围。
- `TripBudget` 使用 `Decimal`，区分 hard/flexible；硬预算不允许额外弹性。
- `HardConstraints` 包含每日时间窗、必去/排除地点、固定预约和每日活动上限。
- `SoftPreferences` 保存兴趣、节奏、出行方式、住宿和餐饮偏好。
- `ClarificationQuestion` 把缺失输入转成可路由、可阻塞的问题。
- `TripRequest` 校验 1～7 天日期范围、`days` 与结束日期一致性，以及固定预约必须在旅行日期内。

`examples/trip_request.beijing.json` 是可直接解析和往返序列化的合成输入。额外或拼错字段会被拒绝，避免错误悄悄进入 Planner。

## 4. C07：Harness 消息契约

提交信息：`feat(domain): define harness message contracts`

`packages/domain/messaging.py` 定义：

- `RunState`、`TaskState` 与 `EventType`，非法状态不能由自由文本混入。
- `Task` 保存依赖、输入 Artifact、尝试次数、期限、幂等键与 trace ID。
- `Event` 是追加式事实，带 correlation/causation/trace 信息。
- `ArtifactRef` 只传稳定 ID、版本和内容哈希，避免在 Agent 间复制大对象。
- `Claim` 将事实判断与 `Evidence` 来源分离；verified/contradicted 结论必须引用证据。
- `Evidence` 保存来源、抓取与有效时间、字段覆盖范围、置信度和存储策略。

## 5. C08：统一旅行数据模型

提交信息：`feat(domain): define canonical travel data models`

`packages/domain/travel.py` 把供应商差异挡在 Tool Adapter 边界：

- `Place` 同时保留 raw 与 canonical 坐标，并引用来源证据。
- `Route` 使用统一交通枚举、距离、耗时、质量标记和坐标系。
- `WeatherForecast` 带抓取时间与有效期限。
- `Lodging` 和 `IntercityTransport` 使用统一价格与可用性语义。
- `CostEstimate` 明确 known/range/unknown，未知价格不会自动变成 0。
- `OpeningSchedule`、`VisitDurationEstimate` 分开表达供应商事实与系统估计。

测试用两个不同形状的模拟 Provider payload 映射到同一个 `Place`，证明业务层不需要知道供应商字段名。

## 6. C09：行程输出契约

提交信息：`feat(domain): define itinerary output contracts`

`packages/domain/itinerary.py` 建立三层输出：

1. `PlanCandidatesArtifact`：一到三个策略不同的候选行程。
2. `ReviewArtifact`：pass/revise/reject 结论、确定性评分、硬违规和有限修复请求。
3. `FinalPlanBundle`：最终计划、对比指标、证据、协作摘要与数据新鲜度。

每个 `ItineraryItem` 都带地点、费用、路线、Claim 和 Evidence 引用。`examples/final_plan_bundle.beijing.json` 可由 Schema 读取、序列化并再次校验；最终 JSON、Markdown 和未来 Web UI 可以共享这一事实源。

## 7. C10：纯合成 Fixture 与 ScriptedModel

提交信息：`test: add synthetic fixtures and scripted model`

`packages/evals/fixtures.py` 使用固定时间、固定 ID、UTC+8 时区和 `Decimal` 金额构造完整场景，包括请求、证据、事实、地点、路线、天气、住宿、交通、候选方案、审校和最终输出。

`packages/evals/scripted_model.py` 是异步模型替身：

- 预先用 Pydantic 校验每轮工具调用或结构化输出。
- `generate()` 只按顺序返回脚本，不读取 Provider SDK、网络或环境密钥。
- 记录输入消息数、工具数和是否请求 Schema，方便测试编排行为。
- 脚本用完后抛出明确的 `ScriptExhaustedError`，不会回退到真实模型。

`fixtures/synthetic/scripted_turns.json` 演示第一轮请求地点工具、第二轮返回固定结果。测试比较完整场景 JSON 的 SHA-256，证明重复构建字节一致。

## 8. C11：确定性校验器

提交信息：`feat(domain): add deterministic validators`

`packages/domain/validators.py` 提供六组纯函数：

| 校验器 | 确定性规则 |
|---|---|
| `validate_budget` | 逐项重算日/计划上下界；检查币种、未知费用、声明总额和预算上限 |
| `validate_time_windows` | 检查活动日期、每日开始/结束边界与活动分钟上限 |
| `validate_overlaps` | 按开始时间排序后检查相邻区间交叠 |
| `validate_opening_hours` | 对照星期开放区间与特殊闭馆日；未知开放时间显式报错 |
| `validate_coordinates` | 确保 canonical 地点和路线采用一致的显式坐标系 |
| `validate_references` | 检查地点、路线、Claim、Evidence ID 及路线端点，未知硬约束阻断执行 |

`validate_itinerary` 以固定顺序聚合所有结果为 `ValidationReport`。调用方依赖稳定的 `ValidationCode`，展示文本可独立调整。hard budget 的超额/未知费用是 error；flexible budget 对应 warning。

测试先证明合法合成方案零问题，再分别构造超预算、时间重叠、时间窗越界、特殊闭馆、坐标系冲突、缺失路线/证据和未知硬约束，确认这些方案不能通过。

## 9. 如何自行复现

```powershell
uv run pytest tests/test_trip_request.py tests/test_messaging.py tests/test_travel_models.py

uv run pytest tests/test_validators.py
```

